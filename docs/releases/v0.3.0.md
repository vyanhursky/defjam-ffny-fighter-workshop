# Fighter Workshop 0.3.0

Offline desktop packages for Windows x64, macOS Apple Silicon, macOS Intel and
Linux x64. Python and Qt are included. Extract the complete package; launch the
executable on Windows/Linux or the `.app` on macOS. Select your own Recomp game
data through **Game setup**. No game dump, runtime executable or save is included.

This release pairs with **Def Jam Recompiled 1.2.0**, which ships the runtime side
of every feature below.

## Changes

- **Final battle attributes and Charisma (CAF).** Stats has an **Attribute mode**:
  keep the original five training inputs, or choose **Final battle attributes
  (0–50)** for Upper power, Lower power, Speed, Toughness, Health and Charisma.
  The values are shared by all outfits and survive outfit navigation, copy,
  Undo/Reset, save and export. Story saves keep their five training fields.
- **Team portraits and icons.** Menu artwork has per-outfit **Team portrait**
  (the tall four-player card) and **Team icon (available/picked)**, with the usual
  import, clear, undo, inheritance and save/reopen. Missing roles keep the donor's
  artwork. Original-artwork staging accepts older 24-role and new 27-role donor sets.
- **Authored entrance cinematics (CAF).** A standalone CAF project can keep an
  authored entrance performance (`fighter-cinematic-caf-performance-2`: donor
  template, timed edits, mouth track and its own intro voice) next to the
  original retail performance choices, and export it with the final attributes
  and sculpt normals intact. Authoring the performance itself (Blender voice and
  mouth controls, half-speed preview) uses the runtime's authoring tools.
- **Sculpt neck-normal corrections.** Projects made with the experimental
  sculpt-v2 format (`ffny-face-sculpt-2`) open again. Their reference-bound neck
  normals are previewed on private copies and kept across mixed-version outfits,
  head OBJ reimport, undo, save and export.

## Runtime compatibility

Each feature exports only when the selected runtime advertises its capability
(`scripts/fighter-contract.json`, Game setup shows it):

| Feature | Runtime capability | First runtime |
|---|---|---|
| Final battle attributes / Charisma | `caf-final-stats-1` | 1.2.0 |
| Team portrait and icons | `fighter-ui-team-art-1` | 1.2.0 |
| Sculpt neck-normal corrections | `caf-sculpt-normals-1` | 1.2.0 |
| Authored entrance cinematic | runtime reads `fighter-cinematic-caf-performance-2` (no separate extension) | 1.2.0 |

An older runtime gets an explicit export error (for an authored entrance, the
runtime compiler refuses the format); opening, editing and saving the project
still work. Projects that use none of these features export to the same
runtimes as 0.2.0.

## Validation and limits

Merged candidate (`release/0.3.0`, Workshop PRs #35, #36, #37, #39): 390 Python tests
passed (5 platform skips), 24 Node tests passed, Ruff check/format and mypy pass.
The export gate checks all three capabilities against the 1.2.0 runtime release
candidate's manifest. Each feature was exercised in its own PR with private real
projects (three-outfit 2Pac: sculpt corrections, final attributes, Team art,
authored entrance) and the matching runtime; the 1.2.0 release candidate records
the combined in-game test of the 2Pac pack, which uses all four.

Each published platform package comes from the tagged source's successful native
CI build and relocated frozen startup check. SHA256SUMS and provenance.json bind
the archives to that exact source commit and CI run. macOS/Linux native CI
build/startup checks are not manual editor/game acceptance. Face sculpt and PS2
recovery remain experimental; keep backups and test exports apart from your main
saves. macOS packages are ad-hoc signed, not notarized.
