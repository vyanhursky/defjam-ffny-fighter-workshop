# Face authoring

This milestone extends the custom meshes and fighter modpack roadmap. Basic
edits use original CAF save fields. Advanced and Expert edits use a standalone
project plus the compatible CAF v4 runtime; geometry is never added to Story saves.

## Basic: original presets

Appearance exposes face type, eye shape/color, eyebrow shape/color, nose, lips
and ears. Shape selectors use original ordinals 1–8; eyebrow colors use the
36 original named palettes, where available. The catalog checks source
objects/textures. Internal `9999` textures are excluded. Ear preset 4 retains
its saved ordinal and explains the original alias to 2. Unknown saved choices
remain visible and preserved until explicitly replaced.

Only selected value/color array slots change. Normal staging, preview, change
review, Undo/Reset, backup, save/copy and project workflows apply. Imported
RGB atlases remain applied across appearance changes; the editor rebinds the
same PNG bytes to the staged outfit. Clear explicitly to restore retail artwork.
Clear a sculpt before changing its body/shape presets.

## Advanced: experimental proportions

Nine bounded controls modify face width, jaw width, chin length, nose width,
nose projection, eye spacing, eye size, eyebrow height and ear size. Values are
absolute -1 to +1 edits against the original head, not cumulative changes.
Smooth spatial masks fade into a protected collar region. These are a prototype,
not recovered retail sliders or anatomically fitted landmarks. Inspect small
edits from several angles. They share the Expert position-only export path.

Applying sliders replaces the previous slider sculpt. Export/preserve and clear
an imported sculpt before switching to sliders. Future landmark fitting/layers
must use an explicit revision rather than reinterpret v1 data.

Dragging previews geometry immediately in the 3D view, using unit-control
deltas generated by the same Python sculpt code as Apply/export. The renderer
blends against the original reference on each frame, so rapid dragging does not
accumulate changes. Apply face proportions stages the preview in Pending Changes;
Save project persists it. Revert preview restores the staged face. Preview alone
does not change the project, Undo history or exported geometry. Changing fighter,
outfit, Undo or Reset discards an unapplied preview. Imported-sculpt restrictions
are explained beside the sliders. Portrait capture requires Apply/Revert first.

## Expert: template sculpt contract v1

1. Create/open a standalone fighter project; choose body and facial presets.
2. Export head OBJ and preserve an untouched reference copy.
3. Sculpt vertex positions. Preserve vertex/triangle order, UV values/indexing,
   native orientation/scale and protected neck vertices. Disable welding,
   remeshing, subdivision and exporter vertex/UV reordering.
4. Import the sculpted OBJ. A rejected import preserves the saved file and
   pending edits. Inspect the preview, including eyes, neck and accessories.
5. Save the editable `.ffnyfighter`; export the mod with the compatible runtime.
   Export head OBJ again to continue sculpting later.

UTF-8 OBJ accepts XYZ `v`, two-component `vt`, triangular `f v/vt` or
`f v/vt/vn`, and ordinary grouping/material/normal metadata. Imported materials
and normals are ignored. Negative indices, topology/UV changes, reordered/welded
vertices, non-finite coordinates and unsupported records are refused.

The template has 710 vertices across render meshes 0–7 and 9, with respective
counts 54/218/70/92/73/51/51/81/20. Original auxiliary mesh 8 is untouched.
Axes are X right, Y up, Z forward in original full-fighter bind space; retain
native units and origin. The bottom 12% of the reference head's Y extent is
protected (1e-6 tolerance). Each axis displacement is limited to 0.6 native units.
These bounds do not guarantee good anatomy or accessory fit.

Project version 5 stores per-outfit `face_sculpt`: `ffny-face-sculpt-1`, the
body/geometry preset basis, canonical reference fingerprint, per-mesh float3
deltas and slider values. Versions 1–4 remain supported. Export regenerates the
reference from original assets, checks its fingerprint/collar, and emits a
hash-bound `caf-face-coordinates-1` resource through CAF v4. The native adapter
compares every reference XYZ with the assembled head before invoking the original
Coordinates morph evaluator. It checks resulting vertices and other loaded CAFs'
buffer hashes. Old runtimes explicitly refuse the new format.

## Evaluation and limits

This supports fitting/sculpting a likeness onto the original template. Arbitrary
scan topology needs registration, retopology, UV/skin transfer, neck stitching,
eye/eyelid/mouth constraints and compatible normals. glTF supports skinning and
morph targets, but a container alone cannot satisfy the game's contracts; see
the [Khronos specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html).

Original rig, weights, normals, facial bone motion, teeth, eyes, hair, bandanas,
facial hair and jewelry are retained, with no automatic refitting. Large edits
can cause shading/intersections. External Blender/DCC round-trips, every preset,
cinematic/Blazin' facial motion and repeated-match/outfit combinations are not
yet broadly qualified. Keep sculpting experimental pending that matrix and
owner playtesting. No packaged release is implied.
